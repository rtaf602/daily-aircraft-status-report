# ติดตั้งระบบหลังบ้าน และเปิดเว็บบน GitHub Pages

ทำตามลำดับ 4 ส่วน ใช้เวลาราว 30 นาที ทำครั้งเดียว
ใช้ **บัญชี Google ที่เป็นเจ้าของไฟล์ Google Sheet ของงานนี้** (ทั้งไฟล์หลักและไฟล์ BACKUP) เพราะระบบหลังบ้านจะเขียนไฟล์ในนามบัญชีนั้น

> ระบบนี้ทดสอบกับตัวจำลองของ Google แล้ว แต่ **ยังไม่เคยรันบน Google จริง** ให้ทำส่วนที่ 3 (ทดลอง) ให้ครบก่อนใช้งานจริง
> ถ้าขั้นไหนไม่ตรงกับที่เห็นบนจอ ให้หยุดแล้วแจ้งผู้พัฒนา

## ส่วนที่ 1 — สร้างระบบหลังบ้านบน Google Apps Script

1. เปิด https://script.google.com แล้วกด **New project** ตั้งชื่อโครงการ เช่น `status602-backend`
2. ในไฟล์ `Code.gs` ลบของเดิมทั้งหมด แล้ววางเนื้อหาของไฟล์ `backend/Code.gs` ทั้งไฟล์
3. แก้ส่วน `SETUP` ด้านบนสุดของโค้ด 2 จุด
   - `accessCode` — รหัสเข้าใช้งานที่ทุกคนในหน่วยต้องพิมพ์ครั้งแรกบนแต่ละเครื่อง ยาวอย่างน้อย 8 ตัว ไม่เว้นวรรค
     **อย่าใช้รหัสเดียวกับรหัสผ่านอื่นของหน้าเว็บ** และควรยาวพอสมควร เพราะเป็นด่านเดียวที่กันคนนอก
   - `contact` — สองบรรทัดที่จะแสดงในแท็บ "คำอธิบาย" ของ Google Sheet (ชื่อผู้ดูแลระบบ และเบอร์โทร)
4. กดรูปเฟือง **Project Settings** ทางซ้าย แล้วติ๊ก **Show "appsscript.json" manifest file in editor**
5. กลับไปที่ **Editor** เปิดไฟล์ `appsscript.json` ลบของเดิมทั้งหมด แล้ววางเนื้อหาของไฟล์ `backend/appsscript.json`
6. กด Save (รูปแผ่นดิสก์) เลือกฟังก์ชัน **setup** ในช่องเลือกฟังก์ชันด้านบน แล้วกด **Run**
7. Google จะขอสิทธิ์ ให้กด Review permissions เลือกบัญชี ถ้าขึ้นหน้าเตือนว่า Google ยังไม่ได้ตรวจสอบแอปนี้ ให้กด **Advanced** แล้วกด **Go to … (unsafe)** จากนั้นกด **Allow**
   (หน้าเตือนนี้ขึ้นเพราะเป็นสคริปต์ที่สร้างเอง สิทธิ์ที่ขอคือดูและแก้ไข Google Sheet ของบัญชีนี้)
8. ดูผลใน **Execution log** ด้านล่าง ต้องขึ้นว่า "ตั้งค่าเสร็จแล้ว" พร้อมลิงก์ **ไฟล์ที่เก็บข้อมูลของหน้าเว็บ**
   ไฟล์นี้ถูกสร้างใน Google Drive ของคุณ เก็บไว้ ห้ามแก้ไขด้วยมือ และห้ามแชร์ให้ใคร
9. กด **Deploy → New deployment** กดรูปเฟืองข้าง Select type เลือก **Web app** แล้วตั้ง
   - Execute as: **Me**
   - Who has access: **Anyone**

   กด **Deploy** แล้วคัดลอก **Web app URL** (ขึ้นต้นด้วย `https://script.google.com/macros/s/` และลงท้ายด้วย `/exec`)
10. ทดสอบ: เปิด URL นั้นในเบราว์เซอร์ ต้องเห็นข้อความ `{"ok":true,"service":"status602","ready":true}`

"Anyone" หมายถึงใครก็เรียกที่อยู่นี้ได้ แต่ทุกคำขอต้องมีรหัสเข้าใช้งานที่ตั้งในข้อ 3 ไม่เช่นนั้นระบบไม่ทำอะไรให้

## ส่วนที่ 2 — ใส่ที่อยู่ระบบหลังบ้านในหน้าเว็บ แล้วเปิด GitHub Pages

11. ใน repo บน GitHub เปิดไฟล์ `build.config.json` กดรูปดินสอ แล้วใส่ URL จากข้อ 9 ในช่อง `backendUrl`

        "site": {
          "backendUrl": "https://script.google.com/macros/s/xxxxxxxx/exec"
        }

    กด Commit changes
12. เข้า **Settings → Pages** หัวข้อ Build and deployment ช่อง Source เลือก **GitHub Actions**
    (บัญชี GitHub แบบฟรีเปิด Pages ได้เฉพาะ repo ที่เป็น Public)
13. เข้าแท็บ **Actions** เลือก **Deploy standalone page to GitHub Pages** แล้วกด **Run workflow**
14. รอจนขึ้นเครื่องหมายถูก ลิงก์ของเว็บอยู่ที่ Settings → Pages

## ส่วนที่ 3 — ทดลองก่อนใช้งานจริง

15. เปิดลิงก์เว็บ พิมพ์รหัสเข้าใช้งาน หน้าเว็บจะเปิดขึ้น และแถบสถานะต้อง **ไม่มี** คำว่า "(เก็บในเบราว์เซอร์นี้)"
16. แถบสีเหลืองด้านบนจะถามเรื่องข้อมูลเดิม เลือกอย่างใดอย่างหนึ่ง
    - **นำเข้า**: เลือกไฟล์ `seed.json` จากโฟลเดอร์ private พิมพ์รหัสผ่านสำหรับ Google Sheet แล้วกด นำเข้า
      ข้อมูลจากหน้าบน Claude (รายการเครื่องบิน ค่าล่าสุด เลข REV ประวัติ และลิงก์ไฟล์ Google Sheet) จะตามมา
      `seed.json` ในชุดไฟล์เป็นข้อมูล ณ วันที่จัดชุดไฟล์ ถ้ามีการ SAVE บนหน้า Claude หลังจากนั้น ต้องขอไฟล์ใหม่ก่อนนำเข้า
    - **ไม่นำเข้า เริ่มใหม่**: แล้วกดป้าย Google Sheet บนหน้าเว็บเพื่อวางลิงก์ไฟล์หลักและไฟล์ BACKUP ของปีงบประมาณ
      **ต้องใช้ไฟล์ Google Sheet เปล่า** ถ้าใช้ไฟล์เดิมที่มีแถวจากหน้า Claude อยู่ รายงานของวันที่ซ้ำกับแถวเดิมจะไม่ถูกเขียนลงไฟล์
17. กรอกรายงานทดลอง กด SAVE แล้วตรวจว่า
    - หน้า "บันทึกสำเร็จ" บอกว่าส่งขึ้น Google Sheet แล้ว
    - ไฟล์หลักและไฟล์ BACKUP มีแถวใหม่ในแท็บ DATA
    - เปิดเว็บจากอีกเครื่องหนึ่ง (หรืออีกเบราว์เซอร์) ใส่รหัสเข้าใช้งาน แล้วเห็นรายงานเดียวกัน
18. จับเวลาตั้งแต่กด SAVE จนขึ้นหน้าบันทึกสำเร็จ แล้วแจ้งผู้พัฒนา (ดูหัวข้อ "สิ่งที่ควรรู้")

## ส่วนที่ 4 — เริ่มใช้งานจริง

19. **เลิก SAVE บนหน้า Claude** ตั้งแต่วันที่ย้าย ถ้า SAVE จากทั้งสองที่ เลข REV และประวัติจะไม่ตรงกัน และแถวใน Google Sheet จะขาด
20. แจ้งลิงก์เว็บและรหัสเข้าใช้งานให้ผู้ใช้ในหน่วย

## การดูแลภายหลัง

- **เปลี่ยนรหัสเข้าใช้งาน**: แก้ `accessCode` ใน `SETUP` แล้วกด Run ที่ `setup` อีกครั้ง ไม่ต้อง Deploy ใหม่ ทุกเครื่องจะถูกถามรหัสใหม่
- **อัปเดตโค้ดหลังบ้าน**: วางโค้ดใหม่ทับ (ใส่ค่าใน `SETUP` เหมือนเดิม) แล้ว **Deploy → Manage deployments → รูปดินสอ → Version: New version → Deploy**
  ที่อยู่ `/exec` จะคงเดิม ถ้าสร้าง New deployment ใหม่จะได้ที่อยู่ใหม่ ต้องแก้ `backendUrl` ตาม
- **เปลี่ยนรหัสผ่านสำหรับ Google Sheet**: ต้องแก้ทั้ง `hashes.sheet` ใน `build.config.json` และ `ADMIN_HASH` ใน `Code.gs` ให้เป็นค่าเดียวกัน (คำสั่งประกอบหน้าจะไม่ยอมทำงานถ้าสองค่าไม่ตรงกัน)

## สิ่งที่ควรรู้

- **ความเร็ว**: ทุกขั้นของ SAVE ต้องเดินทางไปหา Google หนึ่งรอบ การ SAVE หนึ่งครั้งใช้ราว 7 รอบก่อนขึ้นหน้าบันทึกสำเร็จ และอีกราว 12 รอบเบื้องหลังเพื่อส่งเข้า Google Sheet
  จึงช้ากว่าหน้าบน Claude ยังไม่ทราบเวลาจริงจนกว่าจะลองบน Google จริง ถ้าช้าเกินรับได้ ผู้พัฒนารวมขั้นตอนให้เหลือน้อยรอบลงได้
- **ความปลอดภัย**: เว็บเป็นสาธารณะ สิ่งที่กันคนนอกคือรหัสเข้าใช้งาน ซึ่งตรวจที่ระบบหลังบ้านและไม่อยู่ในหน้าเว็บหรือใน repo
  ระบบหลังบ้านแตะได้เฉพาะไฟล์ Google Sheet ที่ลงทะเบียนผ่านหน้าเว็บด้วยรหัสผ่านสำหรับ Google Sheet และการลบแถวในไฟล์ BACKUP ต้องใช้รหัสนั้นเช่นกัน
  รหัสเข้าใช้งานเป็นรหัสร่วม ระบบจึงไม่รู้ว่าใครเป็นคนบันทึก
- **ขีดจำกัดของ Google**: Google ให้บัญชีหนึ่งเขียน Google Sheet ผ่านระบบได้ราว 60 ครั้งต่อนาที SAVE หนึ่งครั้งใช้ 2 ครั้ง การใช้งานปกติจึงห่างจากขีดนี้มาก
  ถ้ามีคน SAVE พร้อมกันจำนวนมากจนเกิน รายการจะเข้าคิวในหน้าเว็บและส่งใหม่เองภายหลัง
- **ถ้าติดต่อระบบหลังบ้านไม่ได้**: หน้าเว็บจะแจ้ง และให้เลือกลองใหม่ หรือทำงานต่อโดยเก็บในเครื่องนั้น (ออก PDF และ Excel ได้ แต่ไม่ถูกบันทึกร่วม)
- **ไฟล์ BACKUP**: ระบบหลังบ้านทำงานในนามเจ้าของไฟล์ ทุกเครื่องที่ SAVE จึงสำรองลงไฟล์ BACKUP ได้ทันที ไม่ต้องรอเจ้าของไฟล์เปิดหน้าเว็บเหมือนบน Claude
